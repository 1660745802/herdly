# 视觉与交互方向：哑光仪器（Matte Instrument）

状态：已实现，全部业务界面都走这一层（`app/src/main/java/dev/herdwatch/ui/design/`）。样式页已删除：它是开发期的脚手架，不该出现在用户的设置里。
本文件是**唯一**的视觉权威。任何界面元素如果无法用本文里的材质、层级和节奏解释，就不要加。

## 1. 为什么是这个方向

Herdly 是一个仪表：它告诉你哪台机器上的哪个 agent 需要你，让你读证据、做决定、发指令。
所以界面应该像一台做工好的仪器面板——哑光、克制、光只从一个方向来，零件看起来是**装上去**的，不是贴上去的。

要避免的两种俗套：

- **扁平 Material 默认件**：卡片浮层、色块按钮、描边输入框，看起来像模板拼装。
- **糖果新拟物**：大圆角+强内阴影+彩色光晕，看起来像 2019 年的 Dribbble 练习。

我们的折中：新拟物的**物理**（一个光源、抬起与凹陷）+ 仪器面板的**材质**（低饱和底盘、单一强调色、无描边、无彩色光晕）。

## 2. 光与材质

- **唯一光源**：左上。因此每个抬起面的高光在左上、阴影在右下；每个凹陷面正好相反。
- **三种材质，没有第四种**：
  - `chassis`（底盘）：页面背景。浅色 `#E7EAF0`，深色 `#15171C`。
  - `lifted`（抬起）：卡片、按钮、按键、开关滑块、选中的分段。
  - `milled`（凹陷）：输入框、分段轨道、终端窗口、骨架屏。
- **层级只由深度决定**，不用填充色变化、不用描边、不用 elevation 叠加。要强调，就抬得更高（`DsElev.deep`）。
- **阴影实现**：两层同心圆角矩形（深/浅各一层，9 次递减 alpha）合成外阴影；内阴影用裁剪后的渐变描边。确定性、API 26 可用、深浅色同一套物理。禁止使用 `Modifier.shadow`（只有单向阴影，会破坏物理一致性）。

## 3. 颜色

| 角色 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| chassis | `#E6EAF0` | `#15171C` | 页面底 |
| lifted fill | `#EDF1F6` | `#1B1E24` | 抬起面 |
| milled fill | `#DBE0E8` | `#101215` | 凹陷面 |
| 主文字 | `#333A46` | `#E8EBF2` | |
| 次文字 | `#5C6572` | `#9AA3B2` | |
| 弱文字 | `#616A78` | `#89929F` | 仅用于非关键信息 |
| 强调（唯一） | `#2E5AAC` | `#7B9BEA` | 选中、焦点、进行中；蓝宝石而非紫蓝 |
| 危险 | `#B23A37` | `#FF8B86` | 仅高风险审批 |
| 正常 | `#24705A` | `#45C7B0` | 状态灯 |

规则：

- **一个屏幕只有一个强调色**在起作用。同时出现两个强调色就是没有强调。
- 状态色只用于 9dp 的灯（自带同色柔光），不做整块背景染色。
- 深色模式不做字面新拟物：面板是"背光"的——抬起面靠顶部 1.2dp 高光边缘与变暗的凹陷区分，阴影退为低透明度黑色。

## 4. 形状与栅格

- 圆角：卡片 24、控件 16、凹陷 14、按键 12、胶囊 999。
- 间距 4dp 栅格：4 / 8 / 12 / 16 / 24 / 32。
- 触碰目标 ≥ 48dp（按键、图标按钮、开关整行可点）。
- 无分隔线优先：分组靠间距与材质区分；必须分隔时用 1dp、18% 不透明度的阴影色，并左右留白。

## 5. 字体

- 无衬线（system）承担界面；**等宽**承担终端、命令、按键标签。
- 字重：常规 400、强调 600。层级靠字重与颜色，**不靠加粗整段或加大字号**。
- 尺寸：28/20/16/14/12/11。终端字号用户可调（9–22，默认 13），行高 = 字号 × 1.3。
- 计数、时长用 tabular 数字（等宽数字），避免跳格。

## 6. 图标

- 自绘 24×24 网格，1.8dp 描边、圆角端点、统一光学尺寸（`ui/design/NeoIcons.kt`）。
- 不混用 Material 图标：线宽与圆度不一致会让界面看起来是拼起来的。
- 图标不是装饰：每个图标必须对应一个动作或状态；没有语义就不加。

## 7. 动效（唯一节奏表）

| 场景 | 时长 | 说明 |
|---|---|---|
| 按下/抬起（阴影翻转） | 120ms | **不缩放**，表面沉入或弹出 |
| 小状态（箭头旋转、计数、颜色） | 160ms | |
| 原地出现/消失（展开、横幅） | 200ms | 高度+淡入淡出 |
| 页面切换 | 240ms | 进入详情时反向滑出 |

- 只有三种缓动：标准（FastOutSlowIn）、减速（进入）、加速（离开）。没有弹簧、没有回弹；循环只用在下条列出的两个进行中指示上。
- 循环动画只有两种，都表达"还在动"：进行中状态灯的呼吸（1200ms）、
  `NeoSpinner` 的细弧旋转（1100ms）。后者只用于"这一处正在取东西"，不遮挡内容、不占整块。
- 终端文字永不做动画。滚动是滚动，不是过渡。
- 系统"移除动画"开启时，全部退化为瞬时切换（`LocalReducedMotion`）。

## 8. 交互状态（每个可点元素必须齐备）

1. 静止
2. 按下（沉入 + 120ms）
3. 禁用（无阴影、文字 45%——但仍要能看清是什么）
4. 选中（抬得更高，或强调色点缀，二选一，不叠加）
5. 加载（骨架或原位进度；列表里的转圈只能是一行 14dp 的边角提示，不能盖住内容）
6. 错误（红色只出现在发生问题的那个元素上，不整页变红）

## 9. 可访问性下限

- 正文对比度 ≥ 7:1，次文字 ≥ 4.5:1，弱文字只用于非关键信息。
- 所有自定义绘制控件带 `contentDescription` / `Role`，可被 TalkBack 读到时能说清"是什么、什么状态、点了会怎样"。
- 字号放大 1.3 倍、屏幕高度 < 640dp、软键盘弹出三种情况下，核心操作不能离开视口。

### 9.1 实测对比度（WCAG 2.2 相对亮度公式）

判定标准：正文/按钮文本按 AA 小字号 **≥ 4.5:1**，次要文字 ≥ 4.5:1，弱文字 ≥ 4.5:1（关键信息一律不降级），大字/图标 ≥ 3:1。
不用 Material You 动态取色（壁纸色会破坏单一光源的材质逻辑），也不用 M3 色调表面填充来表达层级。

| 组合 | 比值 | 结论 |
|---|---|---|
| 主文字 / 底盘（浅） | 9.48:1 | AAA |
| 次文字 / 底盘（浅） | 4.89:1 | AA |
| 弱文字 / 底盘（浅） | 4.53:1 | AA |
| 主按钮文字（白）/ 强调底 | 6.62:1 | AAA |
| 强调（作文字）/ 底盘 | 5.48:1 | AA |
| 白字 / 危险底 | 5.91:1 | AA |
| 警告（作文字）/ 底盘 | 4.58:1 | AA |
| 正常（作文字）/ 底盘 | 4.91:1 | AA |
| 主文字 / 底盘（深） | 15.15:1 | AAA |
| 次文字 / 底盘（深） | 7.05:1 | AAA |
| 弱文字 / 底盘（深） | 5.70:1 | AA |
| 强调（深）/ 底盘（深） | 6.59:1 | AA |
| 危险（深）/ 底盘（深） | 7.93:1 | AAA |
| 正常（深）/ 底盘（深） | 8.58:1 | AAA |

第一版 token 有四处不达标（强调白字 4.24、危险白字 3.74、弱文字 3.01、强调作文字 3.77），已整体下压色阶修正；第二次调整把紫蓝（blurple `#5B4BE8`）换成蓝宝石（`#2E5AAC`），因为紫蓝在深色终端旁显得像消费级 AI 配色，而仪器感需要更冷、更低的彩度。
颜色永不单独承载语义：状态永远同时给灯 + 文字标签。

## 10. 代码契约

- 颜色、间距、圆角、时长只能从 `DsTokens.kt` 取；界面代码里禁止硬编码 `Color(0x…)` 与魔法 dp。
- 材质只能用 `neoRaised` / `neoInset` / `neoState`；控件只能用 `NeoComponents.kt` 里的实现。
- 新控件先在本文件的控件清单里定义状态与尺寸，再进入业务界面；几何图标由 `NeoGlyphTest` 守住内边距与居中。
- 弹层（对话框 / 菜单 / 底部面板 / 提示条）只能用 `NeoDialog` / `NeoMenu` + `NeoMenuItem` / `NeoSheet` / `NeoSnackbarBody`；直接用 Material 的 `AlertDialog`、`DropdownMenu`、`ModalBottomSheet`、`Snackbar` 会带回另一套底色与字阶。
- 页面骨架统一用 `NeoPageHeader`：根页不画返回箭头，副标题固定一行，右侧动作放同一行。三个根页的标题基线必须一致。

## 11. 页面骨架契约

每个页面都是「头部 + 主体 + 固定底座」三段，主体伸缩，底座按内容测量：

```
BoxWithConstraints {                 // 全屏页自己接管 insets
    Column(fillMaxSize) {
        Column(weight(1f)) { … }     // 主体：唯一可伸缩的一段
        Column(dock)                 // 底座：不写 weight
    }
}
```

两条硬规则：

1. **底座必须是外层 Column 的第二个子节点。** 如果它变成 `BoxWithConstraints` 的直接子节点，Compose 会先把它画在左上角，主体再占满整屏 —— 表现就是输入框盖住状态栏。`AgentScreen.kt` 的底座上方留了注释说明这一点。
2. **状态提示只占一行。** 错误 / 操作结果 / 陈旧 / 读取时间共用 `StatusStrip`，按优先级取一条消息 + 一个动作，不再堆卡片。终端高度因此不随状态变化。

insets 归属：根页由 `App.kt` 统一加 `statusBars`；`AgentScreen` 与 `TerminalScreen` 自己 union `statusBars + ime + navigationBars`，`App.kt` 不再重复加。

## 12. 交付仪式

每改一屏，交一张真机截图（浅色 + 深色），用独立测试包 `dev.herdwatch.uxtest` 加本地 fixture，不用生产主机。截图放进 `assets/screens/`，README 引用的那几张必须与当前界面一致。
