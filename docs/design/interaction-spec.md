# 交互与布局规格

回答四件事：**每个页面怎么被打开**、**每个页面的骨架**、**对话模式怎么读一份屏幕**、**状态只说该说的话**。
视觉材质见 `style-direction.md`；范围与验收见 `../product.md`。本文件描述代码当前的样子，末尾列出未做的部分。

## 0. 主线

> 详情页的实体是 **pane**，不是 agent。agent 只是 pane 上的一种角色。

| | 对话 | 终端 |
|---|---|---|
| 是什么 | 与 agent 的会话 + 回复 | 一个 pane 的屏幕 + 敲键 |
| 前置 | 该 pane 上有 agent | 无（有连接即可） |
| 输入 | `agent.prompt` | `pane.send_input`（字面打进 PTY） |
| 附加 | 回复框 | 按键两行 |

## 1. 路由

单 Activity；`AppViewModel` 里 `pageStack: MutableList<Screen>` + `trailRoot: Screen`。

`Screen` = `Inbox | Hosts | Settings | Detail(agentKey) | Structure(hostId) | Terminal(hostId) | Manage(hostId)`。`Detail.agentKey` 就是 `hostId:paneId`，`navigate(Detail)` 直接走 `openPane`，所以 pane 是唯一入口参数。

```
任务 ─ agent 行 ─► Detail(pane)      back → 任务（原滚动位置）
任务 ─ 分屏行 ──► Detail(pane)       back → 任务
机器 ─ 打开终端 ► Terminal(host)     back → 机器
机器 ─ 会话 ────► Manage(host)       back → 机器
会话 ─ 页头图标 ► Structure(host)    back → 会话
结构 ─ 分屏行 ──► Detail(pane)       back → 那棵展开的树
```

- 根标签互切：清空 `pageStack`，`trailRoot` 设为该标签；从机器进设置时 `trailRoot` 保留机器，返回落回机器。
- `push()` 记录来源页（根不入栈、栈顶去重）；`back()` = 关浮层 → pop → `trailRoot` → 退出。回到 `Detail`/`Terminal` 用 `pushPage=false` 重新装载，不再压栈。
- 浮层不占路由：审批面板、选择复制、重命名、删除确认、状态解释。
- 每页状态：滚动位置与暂停按 pane 记（`readingPositions`）、对话/终端选择按 pane 记（`rememberSaveable(agent.key)`）、字号在偏好里。

## 2. 页面骨架

统一：**页头（我在哪）/ 状态条（只说环境事实，多数时候不出现）/ 内容 flex / 底部 dock**。

### 2.1 任务 Inbox（根）

```
页头 Herdly / 分屏与 agent            [搜索] [刷新]
区块 1  N 个 agent（M 个在等你）
  工作区小标题
  一行：● 名字 ………………… 标签 · 分屏号 状态   ← 单行，点进对话
区块 2  devbox · 11 个分屏                        已连接
  工作区标题
    标签页小标题
    一行：● 名字 ………………… 分屏号 状态 [对话/终端图标]
          /完整/目录（~ 缩写 home）
```

- agent 与分屏都按 工作区 → 标签页 分组；同名 agent 靠行尾 `标签 · 分屏号` 区分。
- **没有「需要处理」筛选态**：紧急度只体现在排序（等你 > 工作中 > 其它）和灯色。
- 分屏行覆盖含 shell 的所有 pane；行尾图标说明点进去是对话还是终端。
- 一张卡片装一组行 + 分隔线，末行不单独成卡。连接异常只占一行。

### 2.2 机器 Hosts（根）

```
页头：机器                      [+ 添加]
状态条：1 台机器 · 1 台已连接
卡片： ● 名称                        [⋮ 编辑/删除]
       user@host:port
       已连接 · 5 个 agent ／ 连接失败：原因（2 行截断）
       最后成功同步 12:03
       [ 打开终端 ] [ 会话 ]                 [› 诊断]
```

- 只有两个动作。「检查会话」与「管理」曾是同一棵树的两个视图，已合并成 **会话**。
- 诊断（原始错误、指纹、复制诊断）收在右侧箭头里。
- 密钥变化时主行换成 `核对新密钥`（两个指纹并列，危险色），可逐台接受。

### 2.3 会话 Manage(host)

```
页头 会话 · devbox                        [结构浏览]
新建卡：[ 新工作区 ] [ 新标签页 ]（未连接时禁用并说明原因）
工作区标题  ▾ ⿴ 名字 · N 个分屏          [重命名] [关闭]
  标签卡： ▾ ▭ 标签名             [拆分] [重命名] [关闭]
    分屏行：● 名字 / 短id · ~目录        [重命名] [关闭]
```

- 工作区与标签页都可收起（`rememberSaveable` 记住收起集合），收起时显示分屏数量。
- 新建按钮的图标与下方层级图标一致：工作区 ⿴、标签页 ▭。
- 分屏名字：shell 用目录末段（`base`/`interface`），不显示截断的 `user@host`。
- 拆分放在标签头上（带位置语义），分屏行只留重命名/关闭，名字才有地方。
- 关闭确认写清后果：工作区/标签页说「N 个分屏一起关闭」，分屏说会结束哪个 agent。
- 成功不弹提示（列表变化即回执），失败才说话。

### 2.4 分屏详情 Detail(pane)

```
[←] 名字                              [刷新] [⋮]
    [AGENT 值守 | SSH 终端] ● 状态 时长
    devbox · hyper · project · p2          ← 位置行，永远显示
状态条：仅错误/离线/证据过期/无障碍暂停时出现
[ 对话 | 终端 ]                            ← shell pane 不显示
内容 flex：对话流 或 终端网格（ANSI 原色）
dock：有 agent → 回复框（有审批时出现审批入口）
      shell   → 按键两行（44dp）+ 命令行
```

### 2.5 SSH 终端 Terminal(host)

页头（host / SSH 终端 / 连接灯 / 重连 / ⋮ 字号）→ 等宽网格 flex（底部留 44dp 覆盖条：回到底部 + 按键开关）→ 按键两行 + 输入行。全屏程序（vim/less/tmux）自动进入直通输入并只显示当前屏。

### 2.6 结构 Structure(host)

页头 + 计数；工作区卡 ▸ 标签块 ▸ 分屏行，每级一个 ⋮（聚焦/重命名/新建标签/拆分/关闭），分屏行点进 `Detail`。只负责浏览与跳转，增删改在会话页。

### 2.7 设置 Settings（根）

外观（语言、主题）/ 终端（字号）/ 本机安全（重置指纹）+ 版本号脚注。没有动效、密度、输入模式、按键栏行数、长按连发这些"替设计道歉"的开关。

## 3. 对话：按轮次读，滑到顶静默回溯

### 3.1 单位是轮次，不是气泡流

一个轮次 = 我的一句话 + agent 这一轮的动作（思考、工具、正文）。边界猜错时也只是块内多/少一条，不会把半句话切成两条消息。

边界优先级：`state_change_seq` 跳变 > 输入框 glyph 重新出现 > 块首符号（`⏺ ⎿ ✻`）+ 空行。全失败时并进最后一块，绝不新开。

### 3.2 我发的消息

只来自我们自己的发送记录（`DetailState.sent`，每分屏最近 12 条），**绝不从屏幕猜**。右对齐气泡，发送即落位；快照里出现同样文本（去掉空白后比对末 24 字）时撤掉本地副本。

### 3.3 思考 vs 正文 vs 工具

| | 视觉 | 默认 |
|---|---|---|
| 思考 | 正文上方的折叠注脚 `✻ 思考 · N 行`，弱化色 | 折叠 |
| 正文 | 左对齐抬升卡，比例字体 15sp / 行高 23sp | 展开 |
| 工具 | 折叠卡 `工具 · N 行`，等宽 | 折叠 |
| 系统/审批 | 居中细字 / 风险色卡片 | 展开 |

识别信号：已知前缀（`✻ ✽ ✢`、`thinking:`、`thought:`、`reasoning:`）> 段落位置。解析不可信时退化成一整块正文（去掉装饰行），不弹「无法识别」——切终端模式随时能看原文。

### 3.4 历史：顶部静默回溯

- 读取起点 `PANE_READ_LINES = 1200`；**滑到顶**时 `loadMoreHistory()` 把请求行数翻倍（→2400→4800…上限 19200），直到 `truncated=false`。
- 合并后保持阅读锚点：记录 `firstVisibleItemIndex + offset`，按内容增高的差值回填。
- 协议没有历史游标，"更早"只能请求更长的尾部，每次响应都是上一次的超集。
- 不做：导出完整对话、跨设备同步、全历史搜索。

### 3.5 审批

- 面板给出问题、全部选项与风险；命令原文可展开核对，永不折叠。
- 长期授权类选项二次确认并说明范围；默认焦点在中性项。
- 发送前重读屏幕，证据变了拒绝发送并说明原因；发送后再读一次，屏幕变了才算生效。
- 解析失败时只给原文与手动按键，不给假按钮。

## 4. 终端模式

网格原样（默认不折装饰线，保留 ANSI 颜色，裁掉行尾填充空格）；按键两行 `Ctrl Esc Tab ⇧Tab ⌫ ← →` / `^C ^D ^Z ↑ ↓ PgUp PgDn`，长按连发；输入走 `pane.send_input`；需要决定时一条窄横幅；上翻暂停跟随；`回到底部`/`按键` 放在保留条里，永不压字。

## 5. 状态与失败：只说环境

- **成功就沉默**：发送成功不出现"已送达/已生效"，气泡落位本身就是回执。
- 状态条只放用户侧环境事实：`未连接` / `正在重连` / `本地已缓存，正在刷新`。
- 失败才说话，且必须带下一步：`发送失败：网络中断` + `重试`。
- **不解释 app 自身**：不写"请求已接受，不代表执行成功"这类免责句。不确定性交给数据本身（灯色、状态徽章）表达。
- 唯一保留的诚实提示是协议限制本身（更早内容不可得），那是内容边界，不是 app 的心情。

## 6. 无障碍

图标按钮 48dp + `contentDescription`；分段/开关有 `stateDescription`；折叠块朗读行数与状态；1.3× 字号时状态条保持一行；IME 展开时页头压缩、dock 只留输入行；动效跟随系统「减少动态效果」。
