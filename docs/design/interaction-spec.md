# 交互与布局规格

回答四件事：**每个页面怎么被打开**、**每个页面的骨架**、**对话模式怎么读一份屏幕**、**状态只说该说的话**。
视觉材质见 `style-direction.md`；范围与验收见 `../product.md`；实现分层见 `../engineering.md`。
本文件描述代码当前的样子，不是变更记录；末尾只列尚未做的部分。

## 0. 主线

> 详情页的实体是 **pane**，不是 agent。agent 只是 pane 上的一种角色。

| | 对话 | 终端 |
|---|---|---|
| 是什么 | 与 agent 的会话 + 回复 | 一个 pane 的屏幕 + 敲键 |
| 前置 | 该 pane 上有 agent | 无（有连接即可） |
| 输入 | `agent.prompt` | `pane.send_input`（字面打进 PTY，回车是按键不是换行） |
| 附加 | 回复框 + 指令面板 | 按键两行（键盘弹出时收成一行） |

## 1. 路由

单 Activity；`AppViewModel` 里 `pageStack: MutableList<Screen>` + `trailRoot: Screen`。

`Screen` = `Inbox | Hosts | Settings | Detail(agentKey) | Structure(hostId) | Terminal(hostId)`。
`Detail.agentKey` 就是 `hostId:paneId`，`navigate(Detail)` 直接走 `openPane`，所以 pane 是唯一入口参数。

```
任务 ─ agent 行 ─► Detail(pane)      back → 任务（原滚动位置）
任务 ─ 分屏行 ──► Detail(pane)       back → 任务
机器 ─ 打开终端 ► Terminal(host)     back → 机器
机器 ─ 会话 ────► Structure(host)    back → 机器
会话 ─ 分屏行 ──► Detail(pane)       back → 那棵展开的树
```

- 根标签互切：清空 `pageStack`，`trailRoot` 设为该标签；从机器进设置时 `trailRoot` 保留机器，返回落回机器。
- `push()` 记录来源页（根不入栈、栈顶去重）；`back()` = 关浮层 → pop → `trailRoot` → 退出。回到 `Detail`/`Terminal` 用 `pushPage=false` 重新装载，不再压栈。
- 浮层不占路由：审批面板、选择复制、重命名、删除确认、状态解释、指纹核对。
- 每页状态：滚动位置与暂停按 pane 记（`readingPositions`）、对话/终端选择按 pane 记（`rememberSaveable(agent.key)`，默认按有没有 agent 决定）、字号在偏好里。

## 2. 页面骨架

统一：**页头（我在哪）/ 状态条（只说环境事实，多数时候不出现）/ 内容 flex / 底部 dock**。
页头尺寸与内边距由 `PageBarSpec` 统一（`start/end/top/gap`），标题一律 `DsTypography.headline`。

### 2.1 任务 Inbox（根）

```
页头 Herdly / 分屏与 agent            [搜索] [刷新]
机器块  ● devbox   3 个 agent、3 个分屏   2 个待处理
  AGENT
    工作区小标题
    一行：● 名字 ………………… 标签 · 分屏号 状态   ← 单行，点进对话
  分屏
    工作区标题
      标签页小标题
      一行：● 名字 ………………… 分屏号 shell [终端图标]
            /完整/目录（~ 缩写 home）
────────────────────────────────  ← 极淡分割线
机器块  ● billserver …
```

- 一台机器一块，块间用 `WeakRule`（`textFaint` 12% 的 1dp 线）分隔；机器按 待处理数 → agent 数 → 分屏数 → 名称 排序，刷新时顺序稳定。
- 块头是「状态灯 + 机器名 + `N 个 agent、M 个分屏`」，有待处理时补一句危色计数。
- 块内先 agent 后分屏，两个标签 `AGENT` / `分屏` 都是全大写微字号，不和机器名争层级。
- 宽屏 / 横屏（≥600dp）拆成左右两栏，左侧只 emit agent、右侧只 emit 分屏，两栏各自按同样的机器块组织。
- agent 与分屏都按 工作区 → 标签页 分组；同名 agent 靠行尾 `标签 · 分屏号` 区分。
- **没有「需要处理」筛选态**：紧急度只体现在排序（等你 > 工作中 > 其它）和灯色。
- agent 本体就是 pane，不再在分屏栏里重复列一次。
- 分屏行覆盖含 shell 的所有 pane；行尾图标说明点进去是对话还是终端。
- 一张卡片装一组行 + 分隔线，末行不单独成卡。连接异常只占一行，点进去看原因。
- 离线机器只出现那一行错误，不再渲染它缓存里的 agent 与分屏——列表里每一行都得点得动。

### 2.2 机器 Hosts（根）

```
页头：机器                      [+ 添加]
状态条：1 台机器 · 1 台已连接
卡片： ● 名称                        [⋮ 编辑/删除]
       user@host:port（配了备用地址时写明走了哪条）
       已连接 · 5 个 agent ／ 连接失败：原因（2 行截断）
       最后成功同步 12:03
       [ 打开终端 ] [ 会话 ]                 [› 诊断]
```

- 只有两个动作：打开终端、会话。诊断（原始错误、指纹、复制诊断）收在右侧箭头里。
- 密钥变化时主行换成 `核对新密钥`（两个指纹并列，危险色），可逐台接受；确认前不发送凭证。

### 2.3 会话 Structure(host)

工作区 / 标签页 / 分屏的浏览与增删改都在这一页，没有第二个"管理"视图。

```
页头  devbox / 工作区 / 标签页 / 分屏
汇总卡：N 个工作区 · N 个标签页 · N 个分屏
         [ + 新建工作区 ] [ 启动 agent ]（无已核实空 shell 时禁用并写明原因）
工作区行  ▾ 名字 [当前] · W1 · N 个标签页 · N 个分屏        [⋮]
  标签行  ▾ ● T1 名字 · N 个 agent · N 个分屏 · 状态        [⋮]
    分屏行 ● 名字 · 类型 / 短id · 状态 · 目录  → 点进该分屏的 Detail   [⋮]
  [ + 新建标签页 ]
```

- 三级都是同一个 `⋮`：工作区＝聚焦/重命名/新建标签页/关闭；标签页＝聚焦/启动 agent/重命名/关闭；分屏＝打开/启动 agent/聚焦/重命名/向右拆分/向下拆分/关闭（关闭带分隔线 + 危险色）。重命名与关闭同权重紧邻时误触代价不对称，所以都收进菜单。
- 新建不直接执行，先弹确认层：新标签页要在 `NeoChip` 里选工作区（默认当前聚焦的），可选起始目录（绝对路径 + 最近用过的目录）。没有列目录的 RPC，所以给路径输入而不是假的文件浏览器。
- 收起/展开的点击面是整行 48dp，按下用 `well` 底色 + 圆角；收起集合 `rememberSaveable`，收起时显示分屏数量。
- shell 分屏用目录末段当标题（`base`/`interface`）：终端标题是整串 `user@host`，截断后每行都一样。
- 分屏行点进去和首页点分屏走同一条 `push(Detail)` 路由。
- 关闭确认写清后果：工作区/标签页说「N 个分屏一起关闭」，分屏说会结束哪个 agent。成功不弹提示，列表变化即回执。

### 2.4 分屏详情 Detail(pane)

```
[←] 名字                        [重新读取] [⋮]
    ● 状态 · 时长        devbox · hyper · project   ← 同一行尾部，微字号
状态条：仅错误/离线/证据过期/无障碍暂停/用户暂停时出现
[ 对话 | 终端 ]                            ← 只在能切的那一页出现；纯 shell 不显示
内容 flex：对话流 或 终端网格（VT 颜色，整屏到底）
dock：对话 → 回复框 + [指令]（有审批时先出现审批卡与入口）
      终端 → 按键两行 + 输入框（键盘弹起时按键收成一行）
```

- 页头一行只放一个身份事实：名字在上，位置在下；分屏号不出现在这里（列表行已经给过，挤在这里只会把目录变成省略号）。空闲状态不重复写"空闲"，灯色 + 朗读描述已经说了。
- 终端模式整屏：去掉外卡圆角与左右内边距，网格贴边。对话与终端的切换放在标题栏（一个图标，双向、对每个 pane 都可用），正文里没有切换行，⋮ 里也没有第二个入口。
- 输入走一条路径：`TerminalInputView` 作为真正的 `InputConnection`，候选只在确认时发给 PTY，回车发 `\r`，退格按码点算一个 DEL。没有"普通 shell / 全屏程序"的模式开关。
- 阅读期间保持屏幕常亮（离开页面恢复系统默认）：盯着 agent 跑任务是几分钟不触屏的事。

### 2.5 SSH 终端 Terminal(host)

```
[←] 机器名                  [重连] [⋮]
    ● 已连接 · vim / 账号名        ← 一行一个事实
等宽网格 flex（底部浮两个控制：回到底部 / 按键开关）
[查找条]（⋮ → 查找 时出现，在按键栏之上，不压输出）
按键两行 + 输入框
```

- 标题槽只放一个事实：程序用 OSC 0/2 设的名字（vim/tmux/less），否则显示账号名。bash 每次提示符都把自己发布成 `user@host:cwd`，这种"标题"会被忽略，否则这一行永远是省略号。
- 全屏程序（vim/less/tmux）由 VT 解析器的备用屏幕直接画当前屏，不切换输入模式；备用屏幕期间跟随光标而不是最后一行，否则整屏会被推到视口外。
- ⋮：放大/缩小字号、显示/隐藏按键栏、粘贴、查找、分享屏幕内容。
- 断线：按 1s / 2s / 4s / 8s / 16s / 30s 自动重试，卡片写明「正在重连（第 n 次）」；网络恢复（`ConnectivityManager` 回调）立刻重试一次；认证失败、主机密钥变化、要求动态口令都不重试——没有一次重试能成功。网络不可达用人话说（`ssh_network_down`），不把 `ENETUNREACH` 抛给用户。
- 连接期间保持屏幕常亮；键盘弹出时网格不缩小（PTY 尺寸不变），否则每次开键盘 bash 都会重画一个提示符。

### 2.6 设置 Settings（根）

外观（语言、主题）/ 终端（字号）/ 本机安全（重置指纹）/ 关于（版本、检查更新、下载并安装）+ 版本号脚注。
没有动效、密度、输入模式、按键栏行数、快照行数、长按连发这些"替设计道歉"的开关；动效跟随系统「减少动态效果」。

## 3. 对话：按轮次读，滑到顶静默回溯

### 3.1 单位是轮次，不是气泡流

一个轮次 = 我的一句话 + agent 这一轮的动作（思考、工具、正文）。边界猜错时也只是块内多/少一条，不会把半句话切成两条消息。

边界优先级：`state_change_seq` 跳变 > 输入框 glyph 重新出现 > 块首符号（`⏺ ⎿ ✻`）+ 空行。全失败时并进最后一块，绝不新开。

### 3.2 我发的消息

只来自我们自己的发送记录（`DetailState.sent`，每分屏最近 12 条），**绝不从屏幕猜**。右对齐气泡，发送即落位；快照里出现同样文本（去掉空白后比对末 24 字）时撤掉本地副本。

### 3.3 思考 vs 正文 vs 工具

| | 视觉 | 默认 |
|---|---|---|
| 思考 | 正文上方的折叠注脚 `✻ 思考 · N 行`，弱化色 | 折叠 |
| 正文 | 左对齐抬升卡，比例字体 15sp / 行高 23sp | 展开 |
| 工具 | 折叠卡 `工具 · N 行` + 首行摘要，等宽 | 折叠 |
| 系统/审批 | 居中细字 / 风险色卡片 | 展开 |

- 识别信号：已知前缀（`✻ ✽ ✢`、`thinking:`、`thought:`、`reasoning:`）> 段落位置。解析不可信时退化成一整块正文（去掉装饰行），不弹「无法识别」——切终端模式随时能看原文。
- 折叠按**渲染列宽**算（CJK 占两列），约 18 行；标注真实剩余行数（`展开全部 · 还有 N 行`），单段超预算时在句号处截断。
- 一串同款空药丸是噪音而不是省略，所以折叠行带首行摘要（`工具 · 23 行  $ cd /mnt/data/gpu_perf…`）。
- agent 回答整卡可选中复制；重绘导致的重复段落合并成一份 + `×N`。
- 新一轮出现时 200ms 淡入 + 10dp 上浮，只有最新那一块动，跟随系统「减少动态效果」。

### 3.4 历史：顶部静默回溯

- 读取起点 `PANE_READ_LINES = 1200`；**滑到顶**时 `loadMoreHistory()` 把请求行数翻倍（→2400→4800→…上限 `MAX_HISTORY_LINES = 12_000`），直到 `truncated=false`。
- 取到之前，顶部一行居中细字加小转圈（`agent_reading_older`），不阻塞阅读、不弹 toast。
- 轮次的身份来自**从末尾数起的位置 + 角色**，不来自文本首行：这页读的是视口，一轮回答变长时首行会滚出缓冲区，靠文本做 key 会让读者刚展开的卡片每几秒自己合上。
- 引用块（`>` 开头的提示词）只留提示词本身；它下面出现标题/列表/加粗/围栏时，从那里开始是新的一轮回答——否则整轮会渲染成一个用户气泡，既没有段落节奏，也没有强调。
- 到顶或最大尾部也取不到时，只留一句 `agent_history_end`（「这块分屏只保留最近的屏幕内容，更早的已经滚出缓冲区」），不弹错误条：那是内容边界，不是机器掉线。
- 合并后保持阅读锚点：记录 `firstVisibleItemIndex + offset`，按内容增高的差值回填；等待增高的 effect 以 `historyLines` 为 key，所以一次没取到新内容也不会把锚点永久挂住。
- 读屏取消不再断开连接（`useHost` 对 `CancellationException` 只上抛）；历史读取用 `failFast`，超时不拆会话。
- 协议没有历史游标，"更早"只能请求更长的尾部，每次响应都是上一次的超集。

### 3.5 实时进度

底部一行说明 agent 现在在干什么，依据是**屏幕真的变了**（`DetailState.textChangedAt`）与**版本号真的动了**（`revisionChangedAt`），不是轮询时间：
`正在输出 · N 秒前有更新` → 8s 后 `仍在执行 · 已 N 秒没有新输出` → 界面在重绘但内容没变时 `仍在执行 · 界面在重绘，但没有新内容` → 版本号也冻住才说 `已 N 分钟没有任何变化`。不猜"卡住了"。

### 3.6 指令面板

按 agent 定，不是一份通用列表。优先读当前屏幕画出来的 `/xxx`（该版本权威），其次才是每个 CLI 的少量回退（`AgentCommandCatalog`）；未识别的 agent 不给别家的命令。点选只写进输入框，发送仍由人决定。

### 3.7 审批

- 面板给出问题、全部选项与风险；命令原文可展开核对，永不折叠。
- 作用域写在选项自己身上：`只此一次` / `本会话` / `长期`，由选项措辞判定（`approvalScopeOf`），长期类保留危险色；提示语分开——`含本会话授权选项` 不冒充 `含长期授权选项`。
- 长期授权类选项二次确认并说明范围；默认焦点在中性项。
- 发送前重读屏幕，证据变了拒绝发送并说明原因；发送后再读一次，屏幕变了才算生效。
- 解析失败时只给原文与手动按键，不给假按钮。

## 4. 终端模式（分屏与整机共用）

- 网格原样：保留 VT 颜色与光标位置，裁掉行尾填充空格；远端墨色对比不足时按 `ensureContrast` 提到可读（工具假设浅底终端，我们是深底）。默认自动换行——快照没有横向滚动，不换行等于丢掉右半边。
- 按键条不横向滚动，每键共享行宽：
  - 整机终端：`Ctrl Esc Tab ⇧Tab ⌫ ← →` / `Alt ^C ^D ^Z ↑ ↓ PgUp PgDn`
  - 分屏第一行：`Esc ⇧Tab Tab ⌫ ↑ ↓ ← →`；shell 第二行 `Ctrl ^C ^D PgUp PgDn Enter`；agent 第二行 `Ctrl y n Enter 停`
  - 键盘弹出时收成一行；Ctrl / Alt 是页面级闭锁，按键条与系统键盘共用同一份状态（Alt = 给下一个键加 ESC 前缀）。
- `⇧Tab`、`⌫`、`PgUp`、`PgDn` 以字面字节送出（`ESC[Z`、DEL、`ESC[5~`、`ESC[6~`）：桥接层按键词表没有这些名字，而终端本来就是发字节。这些字节不走输入框提交路径——不追加回车、不占用草稿，否则一个 ⇧Tab 会顺手把半句话执行掉。
- 双指缩放字号（9–22），单指仍滚动；双击网格 = Tab（补全）；长按 = 打开选择面板；按键统一轻触反馈，长按是连发不是六连击。
- 程序发 BEL 时给一次震动（手机没法"叮"一声）；滚动历史 5000 行。
- 查找：⋮ → 查找，在可见缓冲里高亮全部命中并跳转，计数器在输入框右侧（放进输入框里会让人以为丢了焦点）。
- 分享：⋮ → 分享屏幕内容，发出的是去掉 SGR 的文本，粘到聊天里不带 `[0m`。
- 选择面板：整屏文本可选中、可全选、可一键复制，并把屏幕上出现的 http(s) 链接列成按钮（最多 3 个，句末标点已剥掉）点开。只认显式 `http(s)://`，不猜"像域名的文本"。终端常常是链接唯一出现的地方（评审页、CI 日志）。
- 上翻暂停跟随，`回到底部` / `按键` 浮在网格底部但不压字（内容预留一条通道）。

## 5. 状态与失败：只说环境

- **成功就沉默**：发送成功不出现"已送达/已生效"，气泡落位本身就是回执。
- 状态条只放用户侧环境事实：`未连接` / `正在重连（第 n 次）` / `本地已缓存，正在刷新`。
- 失败才说话，且必须带下一步：`发送失败：网络中断` + `重试`。
- **不解释 app 自身**：不写"请求已接受，不代表执行成功"这类免责句。不确定性交给数据本身（灯色、状态徽章）表达。
- 唯一保留的诚实提示是协议限制本身（更早内容不可得），那是内容边界，不是 app 的心情。

## 6. 认证

- 密码登录同时支持 `password` 与 `keyboard-interactive`：不少加固过的 sshd 关掉 password 只留 keyboard-interactive，同一个密码换个字段输进去而已。只有隐藏字段用密码回答；可见字段（用户名、域、选项）不填密码。
- 要求动态口令 / 二次验证的机器直接说明「这台机器要求动态口令或二次验证，Herdly 目前只支持密码和密钥」，并且不自动重连——重试一万次也不会变，而错答一次会消耗一次尝试机会、看起来像密码错了。
- 首次连接必须确认指纹（显示算法名），确认前不发送任何凭证；指纹变化时停止连接并给出逐台核对入口。

## 7. 无障碍

图标按钮 48dp + `contentDescription`；分段/开关有 `stateDescription`；折叠块朗读行数与状态；1.3× 字号时状态条保持一行；IME 展开时页头压缩、dock 只留输入行；动效跟随系统「减少动态效果」。
