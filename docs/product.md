# 产品口径（唯一权威）

本文件定义范围、每页职责与验收标准。历史方案不再保留；实现细节见 `docs/engineering.md`，交互与布局契约见 `docs/design/interaction-spec.md`。

## 1. 定位

手机上可信、好用、可长期使用的 SSH 终端；在此之上读懂远端 AI agent 的状态，并在需要决定时把决定递到眼前。

- 基础层：SSH 客户端（连接、终端、会话管理）。
- 增值层：Herdr 桥接带来的 agent 值守（状态、对话、审批）。
- 没有桥接时，SSH 部分必须完整可用。

不做：云端中继、自动批准、批量操作、文件管理器、编辑器、遥测。

有机器连接时允许后台保持连接：这不是常驻的“后台进程”，退出登录、杀掉应用或断开最后一台机器，服务与通知一起结束。见 §9。

## 2. 基本单位是分屏（pane）

| 分屏类型 | 打开后 | 输入方式 |
| --- | --- | --- |
| 有 agent | 详情页，默认对话模式，可切终端 | `agent.send_keys` / prompt |
| 无 agent（shell） | 详情页，只有终端模式 | `pane.send_input` |
| 整机 SSH | 终端页 | PTY 直连 |

分屏行必须能看出：机器、目录、标签页、分屏号，以及点进去是对话还是终端。

## 3. 信息架构

```
任务（首页）        机器              设置
 ├ Agent 详情       ├ 终端            ├ 外观：语言 / 主题
 │  ├ 审批面板      ├ 会话（增删改）   ├ 终端：字号
 │  └ 终端模式      │  └ 结构浏览      ├ 本机安全：重置指纹
 └ 分屏详情         └ 添加 / 编辑机器   └ 关于：版本 / 更新
```

路由规则见交互规格 §1：真实页面栈，返回沿来路，弹层不进栈。详情的来路只有一条：从哪个列表点进来，返回就回到哪里；详情页内不再左右切换 agent。

## 4. 任务（首页）

- 一台机器一块，块头是主机名、在线状态、`N 个 agent、M 个分屏` 和待处理数；块内先 `AGENT` 后 `分屏`，块间用极淡的分割线。设备多了也能按机器找，而不是在一列混排里翻。
- 机器排序：待处理数降序 → agent 数 → 分屏数 → 名称。刷新时顺序稳定，不会因为一次轮询跳格。
- agent 按工作区分组，行尾 `标签 · 分屏号`；分屏按 工作区 → 标签页 分组，行内给出完整目录与目的地图标（对话 / 终端）。
- 有 agent 的分屏不再在「分屏」里重复出现第二次。
- 需要处理的分屏排在最前，用灯色和顺序表达，不做单独的「需要处理」筛选器。
- 等你的 agent 在列表里就带一行问题预览（只读 60 行、只读等你/未知的那几个、4 秒预算、失败不影响列表），扫一眼就知道该先开哪个；预览单独占一行，不挤掉名字。
- 「完成」和「已看过」是两件事：agent 停下时排在最前（`待复核`），只要它的那一轮结果真的在详情页显示过，就降为 `空闲` 并排到工作中之后。不靠用户手动点掉，也不用重启才恢复。排序优先级照官方客户端的约定：
  `需要你 > 完成未看 > 工作中 > 空闲`；`未知` 跟着「需要你」一起排在前面，绝不沉底。
  （官方客户端用服务端 `herdr.seen` 标签跨端共享这个事实；我们的桥协议 22 没有这个标签，所以在本地按 agent 记录「已显示到第几个完成序号」，只升不降，进程重启后重新按未看处理——宁可多显一次，也不埋掉结果。）
- 连接异常只占一行，点进去看原因；不重复渲染同一台机器的错误。
- 搜索跨机器匹配 agent 名、分屏号、目录、工作区与标签页；无结果时只显示一条空状态。
- 宽屏与横屏（≥600dp）拆成两栏：左 agent、右分屏，两栏都按同一套机器块呈现。

验收：5 个同名 agent 能一眼分清；离线机器不会把列表清空；上滑不会跳动；横屏两栏的机器块与竖屏一一对应。

## 5. Agent 详情

两种模式，切换在页面层而不是终端里：

- **对话**：按轮次拆分的消息；我发出但还没回显的消息立即成气泡；工具与思考默认折叠；审批以内联卡片出现，命令原文永不折叠。
- **终端**：整屏网格（保留颜色与光标位置）+ 按键栏。标题栏右上角一个图标在对话与终端之间双向切换，两种读法对每个 pane 都成立——纯 shell 的分屏也能切到对话读法，agent 的 pane 也能切去看原屏。切换行本身不再占用正文。

共同规则：

- 读取是静默的：不显示请求行数、不显示「读取于」时钟；只有截断时给一句轻提示。证据过期（切换过前后台、状态在读取期间变化）时状态条给出一条「尚未同步」并带「重新读取」，不留死胡同。
- 上滑到顶自动取更早的内容：请求行数从 1200 起翻倍，一直翻到主机说没有更早的了；没有人为的行数上限，顶部显示「正在往前读…」，读完保持阅读位置。协议没有历史游标，"更早"只能是更长的尾部。读不到时三种情况分开说：主机没有更早内容，写一句「这块分屏只保留最近的屏幕内容，更早的已经滚出缓冲区」；读失败，给一个可点的「读取失败，点一下重试」，重试按上次成功的宽度重发；对话与终端两种视图都有这个入口，术语统一为「读取更早内容」。
- 刚结束的这一轮默认展开全文，只有更早的轮次折叠：最新答案是读者正在找的东西，把它折成十几行再加一个「展开」是最直接的"内容太少"。
- 阅读时自动暂停刷新，回到底部自动恢复。
- 有多个 agent 等着时，输入框上方给一个「下一个待处理 · <名字>」，答完一个直接跳到下一个，不用退回列表再找。
- 成功不说话：消息出现在对话里、分屏出现在列表里，就是回执。只有失败与本机环境问题（未连接、重连中、网络慢）才提示，并且必须给出下一步。
- 不写「不代表执行成功」「可能不完整」这类免责话术。

### 5.1 审批

- 卡片给出问题、选项与风险；命令原文可展开核对。
- 长期授权类选项需要二次确认，并说明确认的范围。
- 发送前重新读取屏幕，证据变了就拒绝发送并说明原因。
- 发送后再次读取：屏幕变了才算生效；没变则如实说明「屏幕没有变化」。

### 5.2 交互选项（含切换模型）

- 切换模型没有专门的流程：指令面板把 `/model` 填进输入框，由你发出，选项列表是 CLI 自己在屏幕上画的。模型名与可用性都属于 CLI，版本与账号不同就不同，应用不维护一份会过期的名单，也不替你回答。
- 终端正在画"一列带指针的选项"时——模型列表、权限确认、diff 审阅、会话选择都是这个形状——输入框旁出现「交互选项」入口。列表来自终端当前画面，解析只认屏幕上真实存在的选项：必须有指针，光有编号的输出（构建日志、shell 提示符）不算菜单，宁可不弹入口也不猜。
- 点一项只是选中，再按一次确认才发送；圆点标出分屏的指针现在停在哪一行，和你选中的行可以不是同一行。发送的是终端自己的按键：按方向键把指针移到所选行，再回车，不输入任何文字，所以没有编号的确认框一样能用。发送前复核屏幕，证据变了就不发。选项表打开期间画面冻结，不会被三秒轮询抽走；真的变了就红字说明「没有发送」并给出重新读取，这条提示会留到你处理为止，不会被下一次轮询抹掉。
- 屏幕上没有可认的选项就不出现入口；离线时说明未连接。发送与手动发送走同一条链路：同样的连接检查与操作锁，发送后自动再读一次屏幕。
- 终端里两类行分开处理：正文按屏幕宽度折行；框线和表格保持原样单行显示，可以左右拖，不会被折成几截。

## 6. 终端

- 真实 PTY：颜色、窗口尺寸随屏幕与字号变化、断线重连。
- 输入是一条直通链路：键盘、候选词、退格、方向键都直接变成 PTY 字节，没有本地编辑缓冲，也不需要用户选模式。回车＝`\r`，删除 emoji 只发一个 DEL。
- 按键两排，不横向滚动：整机终端 `Ctrl Esc Tab ⇧Tab ⌫ ← →` + `Alt ^C ^D ^Z ↑ ↓ PgUp PgDn`；分屏第一排 `Esc ⇧Tab Tab ⌫ ↑ ↓ ← →`，shell 分屏第二排 `Ctrl ^C ^D PgUp PgDn Enter`，agent 分屏第二排 `Ctrl y n Enter 停`。键盘弹出时收成一行。Ctrl / Alt 都是页面级闭锁，按键条与系统键盘共用同一份状态。
- `⇧Tab`、`⌫`、`PgUp`、`PgDn` 以字面字节送出（`ESC[Z`、DEL、`ESC[5~`、`ESC[6~`），不追加回车、不占用输入框草稿。
- 对话模式不显示按键栏：那里是回复，不是终端。
- 终端页整屏呈现：无卡片圆角、无边距，滚动位置与字号随窗口尺寸重排后重连一次 `resize`。
- 断开时屏幕中央一张卡片写清原因，并给「重连」；输入框换成「未连接，重连后才能输入」并禁用发送，不留一个按不动的按钮。
- 可恢复的失败（拒绝、超时、网络不可达）自动按 1 / 2 / 4 / 8 / 16 / 30 秒重试，卡片写明「正在重连（第 n 次）」，六次后停下等人处理；网络恢复立刻再试一次。密码错误、指纹不符、需要动态口令不重试 —— 重试不会让它们变对。

## 7. 机器与会话

- 机器卡片只有两个动作：打开终端、会话；诊断收在右侧箭头里。
- 会话页做完增删改：新建工作区 / 标签页、拆分、重命名、关闭；分组可收起，按压底色覆盖整行。
- 新建不让用户猜：标签页必须选目标工作区（默认当前聚焦的那个），工作区与标签页都可以填起始目录（绝对路径，带「最近用过」），留空用 Herdr 的默认目录。
- 会话页里点分屏，与首页点同一行走同一条路由。
- 关闭类操作必须说清后果（会关掉几个分屏、里面的进程会结束）。
- 一台机器可以配两个地址：主地址 + 备用地址（各自的端口）。同一个用户、同一份凭证、同一个指纹；先连主地址，只有在地址根本连不上（拒绝、超时、解析失败）时才换备用地址。密码错误或指纹不符不会切换 —— 那是判断问题，不是路由问题。卡片在连上时写明走了哪条路。
- 首次连接必须确认指纹（终端页弹框、机器卡片「确认主机密钥」，都显示算法名）；指纹变化时停止连接，并在卡片上给出「核对新密钥」，可逐台接受。确认之前不发送任何凭证。

## 8. 设置

只放习惯，不放用来掩盖设计问题的开关：

| 项 | 取值 |
| --- | --- |
| 语言 | 跟随系统 / 简体中文 / English |
| 主题 | 跟随系统 / 浅色 / 深色 |
| 终端字号 | 9–22 |
| 重置主机指纹 | 破坏性操作，二次确认 |
| 关于 / 更新 | 版本号；手动检查 GitHub Releases，应用内下载并安装 |

排版节奏、动效强度、按键栏行数、输入模式、快照行数都是产品决定，不暴露给用户。动效跟随系统的「减少动态效果」。

## 9. 后台与更新

**后台保持连接。** 有机器时应用运行一个前台服务，通知栏写明连接了几台、有多少待处理；最后一台机器断开、或用户退出应用，服务与通知一起结束。前台每 5 秒同步，后台降到 20 秒；回到前台立即刷新一次。切到后台不再断开 SSH，也不再清空页面证据。

**应用内更新。** 设置 → 关于 → 检查：读取 GitHub Releases 最新版本，有新版本时显示版本号与更新说明，点「下载并安装」在当前应用内下载（显示百分比）、校验包名与本机版本号、再交给系统安装器；首次需要用户在系统设置里允许 Herdly 安装应用，之后直接进安装器。不跳浏览器，不下载网页，安装包过期或不是 Herdly 时明确报错而不是弹一个解析失败。

## 10. 文案

- 中文优先，英文等宽预算内不截断；术语统一：工作区 / 标签页 / 分屏 / 会话。
- 失败文案＝现象＋下一步；成功文案尽量不出现。
- 不在界面上解释实现（行数、快照来源、解析置信度）。

## 11. 验收

每页都要过：真机操作一遍主流程；深浅色各一张截图；1.3 倍字号与键盘弹出不遮挡；TalkBack 能读出行身份与按钮状态；返回沿来路。

## 12. 参考官方客户端

读了官方仓库（`herdrdev/herdr-app` 的窗口与产品模型、`herdrdev/herdr-core` 的会话协议），下面这些已经落地，写在这里是为了以后改动能被它们拦住：

- **`完成 ≠ 已看过`**（§4）：分屏的终态叫「完成」，只有当它当前这一轮之后没人看过时才算「待查看」；进过页面就记为看过，同一个分屏在所有地方同时变「空闲」。规则和官方一致：只升不降，一次进入只写一次。
- **按需才提醒**：单独的提醒渠道（值守提醒）。被阻塞、报错、需要输入时一定提醒；只是完成时，只在你没看着这一屏时才提醒；重连后第一次拿到的快照不补发历史提醒。
- **状态来自程序自己（OSC 7501）**：终端页解析程序上报的 `state/kind/progress/turn`，在标题行显示一个小状态条（`blocked · permission`、`working · 40%`）。有上报就用上报，没有就什么也不显示——不猜。这条让「只装了 Claude Code 的机器」也能说明自己在干什么。
- **机器按最急的一个定调**：机器卡片标题右侧写这台机器上最急的 agent 状态（等你 > 完成未看 > 工作中），而不是一个没有信息量的在线点。
- **失败要给出下一步**：连接失败详情里直接写主机侧要跑的检查命令，而不是让人自己猜。
- **隔离沙箱**：`tools/sandbox.sh` 把验证固定成 `up / status / shot / do / down`：先停正式包，只跑测试包，主机在回环口，结束只杀它自己起的进程。

还没做、也还没到必须做的：

1. **子 agent（没有分屏的 worker）**：官方把 agent 自己起的终端挂在父 agent 之下，可 `peek` 看一眼、`keep` 升成正式分屏。我们的桥只报分屏，所以子 agent 目前看不到。
2. **只报已确认的链接**：官方只把能验证存在的终端名做成链接。我们的识别已经比较保守，但没有「这条地址是否真的存在」的概念。
3. **远端缺组件时帮装**：官方在远端缺 `hc` 时征得同意后安装。我们现在只给出检查命令。
